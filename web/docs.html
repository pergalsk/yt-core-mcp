yt-core-mcp is an MCP server that lets an AI assistant manage your own YouTube channel through the official YouTube APIs. It runs only on your computer. New? Start with the Quick guide.

Setup

  1. Google Cloud project (one time): in Google Cloud Console create a project, enable YouTube Data API v3 (and YouTube Analytics API for analytics).
  2. Consent screen: Google Auth Platform → Branding / Audience, user type External, add the channel owner as a test user, then Publish app → In production. In Testing mode Google expires the login after 7 days.
  3. OAuth client: Clients → Create client → Desktop app, download the JSON and save it as %APPDATA%\yt-core-mcp\client_secret.json (macOS/Linux: ~/.config/yt-core-mcp/client_secret.json) or set YT_CORE_MCP_CLIENT_FILE.
  4. Build: npm ci && npm run build (Node.js 26+).
  5. Log in in a terminal: node dist/bin.js auth.

Connect an MCP client

Claude Code:

claude mcp add yt-core -- node D:/Projects/yt-core-mcp/dist/bin.js

Claude Desktop (claude_desktop_config.json) or any client with a JSON config:

{
  "mcpServers": {
    "yt-core": {
      "command": "node",
      "args": ["D:/Projects/yt-core-mcp/dist/bin.js"],
      "env": { "YT_CORE_MCP_MEDIA_ROOT": "D:/Media/YouTube" }
    }
  }
}

After you rebuild or change permissions, reconnect the server (in Claude Code: /mcp).

CLI reference

CommandWhat it does
node dist/bin.jsStarts the MCP server (your MCP client runs this).
authLog in with the core permission (opens the browser).
auth --add <group>Add engagement or analytics. Keeps groups you already have.
auth --add allAdd every group at once. Optional — asks for the most access.
auth --statusShow the client file path and granted groups.
auth --logoutRevoke the token at Google and delete it from this computer.
auth --helpShow help.

--add can be repeated. captions and comments still work as older names for engagement.

How it works

Login (terminal only)

  1. You run auth
  2. Browser opens Google
  3. You approve
  4. Google sends a code to 127.0.0.1
  5. App checks it and gets a refresh token
  6. Token saved in Credential Manager

A tool call

  1. AI assistant
  2. yt-core-mcp
  3. Permission check
  4. Your confirmation (risky actions)
  5. YouTube API
  6. Result back to the AI

The server keeps one sign-in client in memory, so it does not refresh the access token on every call. It reloads after you log in, log out or add permissions.

Security

  • Secure login: OAuth 2.0 for installed apps with PKCE and a random state check. Google redirects only to 127.0.0.1 on a random port, with a 5-minute timeout.
  • Login only in a terminal: the AI assistant cannot start a login, add permissions or see your tokens.
  • Least privilege: only the basic YouTube permission by default; others only when you add them.
  • Token storage: the refresh token is kept in Windows Credential Manager (macOS Keychain / Secret Service). Access tokens are kept only in memory. auth --logout revokes the token at Google.
  • Confirmations: you must confirm deleting, replying to comments, publishing a broadcast and making anything public or unlisted. If your client can't ask, the action is refused.
  • Untrusted content: titles, descriptions and comments are marked as untrusted, so the AI treats them as data, not instructions.
  • File guard: files are read only from the one folder you allow. No links or escapes, type and size checked (thumbnail JPEG/PNG 2 MB, video MP4/MOV/MKV/WebM 256 GB, caption SRT/VTT 100 MB).
  • No cloud: no server, no database, no tracking. Only official Google APIs.

You can remove access any time in your Google account permissions. See also the Privacy Policy.

Quota

  • The YouTube Data API gives each project 10,000 units per day by default. Most reads cost 1, most writes 50.
  • Video uploads and public search have their own daily limits (100 calls per day each by default).
  • Analytics uses the YouTube Analytics API quota.
  • Sources: quota costs, revision history.

Troubleshooting

ProblemFix
Not logged inRun node dist/bin.js auth.
Permission "…" not grantedRun node dist/bin.js auth --add <group> (or --add all), then reconnect the server.
Login expired or was revokedLog in again. If it happens every 7 days, publish the app In production.
OAuth client file not foundSave the JSON to the default path or set YT_CORE_MCP_CLIENT_FILE.
Client does not support elicitationYour MCP client can't show confirmations; use one that can (e.g. Claude Code).
Uploaded videos stay privateUnverified API projects can only upload private videos until they pass a YouTube audit.
File upload refusedSet YT_CORE_MCP_MEDIA_ROOT and put the file inside that folder.
